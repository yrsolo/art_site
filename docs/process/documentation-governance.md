# Documentation Governance

## Принцип

Документация должна помогать работе, а не конкурировать с кодом.

## Правила

- обзорные вещи держать в `README.md`;
- устойчивые знания держать в `docs/`;
- временные заметки держать в `work/`;
- не выдавать планируемое за реализованное;
- при расхождении кода и docs править docs как можно раньше.

## Для Этого Репозитория

Пока кода немного, документация временно описывает целевую архитектуру MVP. Такие договорённости нужно помечать как плановые и пересматривать после появления реальной реализации.

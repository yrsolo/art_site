# Ideal Principles

## Базовые Принципы

- Простота важнее абстрактной «идеальности»
- Один репозиторий лучше нескольких сервисов на старте
- Визуальная часть и контент-управление должны жить в одном приложении
- Данные и изображения должны быть логически разделены
- Архитектура должна позволять перейти от JSON к БД без тотальной переделки
- Дизайн должен быть заменяемым слоем, а не источником хаоса в структуре

## Что Избегаем

- преждевременной микросервисности;
- лишней ORM-магии, если данные пока простые;
- тяжёлой auth-системы, когда нужен один админ;
- жёсткого смешивания UI шаблонов с бизнес-сущностями;
- зашивания секретов в код и docs.

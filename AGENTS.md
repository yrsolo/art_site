# AGENTS.md

Этот файл задаёт обязательные правила работы агента в этом репозитории.

## 1. Основной Принцип

Не работать хаотично. Любое заметное изменение должно оставлять понятный след в коде, документации или tracking-файлах.

## 2. Перед Началом Работы

Перед реализацией агент обязан:
1. Прочитать [README.md](README.md)
2. Прочитать [docs/README.md](docs/README.md)
3. Прочитать [agent/OPERATING_CONTRACT.md](agent/OPERATING_CONTRACT.md)
4. Проверить [work/now/current-task.md](work/now/current-task.md)
5. Если задача заметная, обновить [work/now/plan.md](work/now/plan.md)

## 3. Source Of Truth

Документация не считается истиной автоматически.

При важных утверждениях сверять:
- код;
- конфиги;
- env-схему;
- runtime entrypoints;
- деплой-конфигурацию;
- реальные интеграции.

Если кода ещё нет, фиксировать договорённости как `planned`, а не как будто они уже реализованы.

## 4. Работа С Документацией

Иерархия документации:
- корневой `README.md` — обзор проекта;
- `docs/overview/` — быстрый вход;
- `docs/architecture/` — архитектурные решения;
- `docs/reference/` — прикладные справочники;
- `work/` — временный рабочий слой.

Не дублировать одно и то же в нескольких местах без причины.

## 5. Tracking Обязателен

Если работа больше маленькой локальной правки:
- обновить `work/now/current-task.md`;
- при необходимости обновить `work/now/plan.md`;
- после этапа обновить `work/now/evidence.md`.

## 6. Ограничения Для MVP

Не раздувать проект раньше времени:
- без сложной CMS;
- без многопользовательских ролей;
- без тяжёлой БД, если JSON-хранилища достаточно;
- без ненужного деления на много сервисов;
- без «идеальной enterprise-архитектуры» ради самой архитектуры.

## 7. После Завершения Этапа

Агент должен:
1. Обновить затронутые docs
2. Прогнать релевантные проверки
3. Обновить evidence
4. Явно отметить, что осталось нерешённым

## 8. Особенность Этого Репозитория

В проекте есть несколько дизайн-эскизов в `ref/template/`.
Пока финальный стиль не выбран, реализация должна по возможности сохранять общий backend-контур и позволять переключаться между визуальными вариантами без переписывания ядра данных и админки.

# Operating Contract

## Цель

Поддерживать управляемую, проверяемую и эволюционную разработку сайта-портфолио без лишней бюрократии.

## Инварианты

1. Код важнее prose при конфликте
2. Важные договорённости должны быть найдены в понятном месте
3. Временное не должно маскироваться под постоянное
4. Простота MVP важнее преждевременной универсальности
5. Секреты не попадают в git и публичные docs

## Режим Работы По Умолчанию

- лёгкий и практичный;
- без полного аудита на каждый шаг;
- с обновлением tracking только когда это реально помогает;
- с фокусом на рабочий результат.

## Обязательные Проверки Перед Заметным Этапом

- актуален ли `work/now/current-task.md`;
- не противоречат ли docs текущему состоянию репозитория;
- не нужны ли обновления `.env.example` и deploy-описаний.

## Критерий Качественного Изменения

Изменение считается качественным, если:
- понятно, зачем оно внесено;
- понятно, где его продолжать;
- оно не создаёт скрытый хаос для следующего этапа.

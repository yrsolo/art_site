Задача:
Нужно сделать сайт для художницы. Публичная часть — простой аккуратный сайт-портфолио с галереей картин, страницами работ, краткой информацией об авторе и контактами. Также нужна закрытая админка, через которую можно добавлять новые картины, загружать изображения, редактировать описания, менять порядок показа и скрывать/удалять работы.

Ограничения и контекст:
- Проект должен быть максимально простым по архитектуре.
- Фронт и бэк должны жить в одном репозитории.
- Деплой планируется в Яндекс Облако.
- Cloud Functions использовать нежелательно, так как лимиты уже почти исчерпаны.
- Предпочтительный вариант деплоя: один Docker-контейнер в Serverless Container / Cloud Container.
- Сайт небольшой, без сложной бизнес-логики.
- Важно, чтобы MVP можно было быстро запустить и потом спокойно расширять.

Выбранные технологии:
- Next.js
- TypeScript
- Tailwind CSS
- Один монорепо / один app-проект без разделения на отдельные фронт- и бэк-репозитории
- Docker для деплоя
- Yandex Object Storage для хранения изображений
- На старте без полноценной БД, если это не усложняет код
- Метаданные работ можно сначала хранить в JSON-файле или в Object Storage
- Вход в админку через пароль, проверка на серверной стороне
- Сессия через httpOnly cookie

Почему такой стек:
- Next.js позволяет держать публичные страницы, админку и API в одном проекте
- Tailwind подходит под уже сгенерированные HTML-шаблоны и их легко переносить в компоненты
- Один контейнер упрощает деплой и не требует распиливать проект на функции
- Для MVP нет смысла сразу поднимать сложную инфраструктуру

Что есть на старте:
- Есть HTML-шаблон сайта, сгенерированный генератором
- Его не нужно использовать буквально как финальный код, но можно брать как визуальную основу
- Стиль шаблона можно адаптировать под реальную художницу
- Шаблон нужно перевести в нормальную структуру Next.js-компонентов

Цель MVP:
Сделать рабочую первую версию сайта, которую можно задеплоить и реально использовать, без лишней сложности.

В MVP должно быть:
1. Публичная часть:
- Главная страница
- Блок/страница “Об авторе”
- Галерея картин
- Страница отдельной картины
- Контакты

2. Данные по картинам:
Для каждой работы нужны поля:
- id
- slug
- title
- description
- year
- size
- medium / technique
- status (available / sold / hidden)
- imageOriginal
- imagePreview
- order

3. Админка:
- Страница логина
- Защищённый раздел /admin
- Список картин
- Создание новой записи
- Редактирование записи
- Удаление или скрытие
- Загрузка изображения
- Изменение порядка показа

4. Бэкенд/API:
Нужны серверные endpoints для:
- login
- logout
- get artworks
- create artwork
- update artwork
- delete/hide artwork
- upload image

5. Хранение файлов:
- Изображения сохраняются в Object Storage
- Метаданные на старте можно хранить в JSON
- Структуру сделать так, чтобы позже было несложно перейти на PostgreSQL или YDB

Требования к реализации:
- Код должен быть чистым и не переусложнённым
- Компоненты должны быть понятными и разнесёнными по смыслу
- Не надо тащить тяжёлые библиотеки без необходимости
- Не надо делать “идеальную enterprise-архитектуру”
- Важно сделать хороший MVP, который потом можно развить
- Нужна удобная структура проекта и минимально разумная безопасность

План на MVP:
Шаг 1. Поднять базовый Next.js-проект с TypeScript и Tailwind
Шаг 2. Перенести текущий HTML-шаблон в layout и React-компоненты
Шаг 3. Сделать публичные страницы:
- home
- gallery
- artwork/[slug]
- about
- contacts
Шаг 4. Описать модель artwork и временное хранилище данных
Шаг 5. Сделать серверную авторизацию в админку по паролю
Шаг 6. Сделать /admin со списком работ и формой редактирования
Шаг 7. Сделать загрузку изображений в Object Storage
Шаг 8. Подключить чтение/запись метаданных
Шаг 9. Подготовить Dockerfile и конфиг для деплоя в Яндекс Облако
Шаг 10. Проверить полный сценарий:
- логин
- добавление картины
- загрузка изображения
- отображение на публичном сайте
- редактирование
- скрытие/удаление

Что не нужно делать в MVP:
- многопользовательскую систему ролей
- сложную CMS
- блог
- корзину / оплату
- i18n
- сложный поиск
- сложные анимации ради анимаций
- тяжёлую базу, если можно обойтись без неё

Что важно предусмотреть сразу:
- чтобы потом можно было без боли заменить JSON-хранилище на БД
- чтобы изображения и метаданные были логически отделены
- чтобы публичная часть не зависела от админки по структуре UI
- чтобы оформление было легко менять под стиль художницы

Ожидаемый результат от агента:
Нужно не просто описание, а стартовая рабочая кодовая база MVP:
- Next.js проект
- базовая структура страниц и компонентов
- админка с логином
- CRUD для картин
- загрузка изображений
- подготовка к деплою в контейнер
